# Приёмка единого плагина A01–A14 на штатном Windows-клиенте

Сценарии A01–A14 взяты дословно из поручения владельца (приватный бриф вне git, раздел 11,
таблица «ID — Сценарий — Проверяемый результат»); решение 0013 § 8, задача
[#112](https://github.com/renidere/sound-scout-plugin/issues/112). По
[решению владельца](https://github.com/renidere/sound-scout-plugin/issues/112#issuecomment-7024498454)
таблицу, проверки станции и записи ведёт агент; владелец делает только настоящие записи и клики в
Windows (шаги O1–O9) и продуктовые решения. Порядок —
[Decision](https://github.com/renidere/sound-scout-plugin/issues/112#issuecomment-7112666148).
Моки, чтение исходников и тесты без настоящего клиента — не приёмка. Мок модели не доказывает
слух. Непроверенное отмечено явно и не считается пройденным.

## Словарь статусов

- `пройдено` — только с evidence: ссылка на комментарий issue с job id, на коммит или на прогон CI,
  дата, стенд. Evidence из одних файлов `tests/` статус `пройдено` не даёт.
- `частично` — какая часть пройдена (с evidence), какая нет и почему.
- `не пройдено` — факт отказа и ссылка.
- `не проверено` — причина (нет входа в UI, вред живой системе, нет второго подключения); при
  наличии — контрактные тесты с пометкой «контракт, не приёмка».
- `ждёт владельца: Oн` — номер шага владельца.
- `ждёт #N` — открытая задача с URL.

## Как агент проверяет

Только чтение. Точка отсчёта T0 — время сообщения владельца «начинаю». После «готово»:

- `<data_root>/jobs/*/job.json` с `submitted_at ≥ T0`: `binding.submitter`, `state`,
  `state_reason`, `attempts[].run_id`, `retries[].after_state` (отмена и повтор: `cancelled` перед
  повтором), `delivery.state`, `delivery.confirmed_by`, `staging_removed_at`.
- `sound-scout jobs status <job_id> --json` (только чтение): `finished_stages`, `cancel_requested`;
  либо записи этапов `work/stage-<этап>.json` в run последней попытки.
- `result.json` в run последней попытки: `status` результата и статусы этапов.
- `~/.hermes/state.db` (`mode=ro`): голосовые `@file:…sound-scout-*.wav` и метки по чатам после T0.
  Hermes записывает историю чата повторно: вторая копия строк имеет больший `id` и тот же
  `timestamp`. Поэтому считаются различные сообщения: роль `user`, метка `sound-scout-job:<job_id>`
  (у заметки повтора — `sound-scout-job:<job_id>-a<n>`, #187) отдельной строкой целиком,
  группировка по `timestamp`. У Y после T0 нет меток, голосовых и
  `internal_notification`.
- `~/.hermes/logs/agent.log`: вызовы `mcp__speech_review__*` в ходах после «Отправить»; `ws closed` и
  `ws_ticket_minted`.
- `<data_root>/runs/`: `report.md` есть; новых run вне заданий после T0 — ноль.
- В этот документ и в issue не попадают названия чатов, текст речи, транскрипт, IP и абсолютные
  личные пути.
