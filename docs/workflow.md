# Автономная работа через задачи

Проект ведётся как бэклог GitHub-задач, которые разбирает автономный агент — по образцу
`em-backlog` из `Evolve-Media-AI/em-ai-skills`, адаптированному под один Python-репозиторий и
ветку `main`. Скилы лежат в `.claude/skills/` и подхватываются Claude Code при запуске в этом
checkout.

## Доска

https://github.com/users/renidere/projects/1 — одна колонка Status:

| колонка | смысл |
|---|---|
| **Backlog** | ждёт агента; очередь — по дате создания, старые первыми |
| **In Progress** | агент работает; на задаче есть claim-комментарий |
| **Need a Person** | нужен человек: разрешение, данные, ручной шаг, или две неудачи подряд |
| **Done** | закрыто |

Эпики (метка `epic`, с подзадачами) в очередь не попадают и закрываются, когда закрыты все
подзадачи. Задача с открытой связью «blocked by» или строкой `Зависит от` с открытой задачей
пропускается, пока блокеры не закрыты.

Метки: `bug` / `enhancement` / `spike`; `priority:blocker|critical|major|minor|trivial`;
`area:*` (core, audio-io, acoustics, asr, audio-backend, eval, reports, cli, mcp, hermes, security,
infra, docs); `permission-required` — часть работы требует разрешения владельца;
`need-a-person` — шаг целиком человеческий (карточка сразу в Need a Person).

## Скилы

| скил | что делает |
|---|---|
| `new-task` | завести задачу: контекст, ссылки на R/T, критерии приёмки, зависимости, метки, карточка в Backlog |
| `work-task <url>` | довести одну задачу до конца без вопросов (см. ниже) |
| `work-backlog [N]` | крутить `work-task` по Backlog без присмотра, N задач параллельно (по умолчанию 1), итог в `backlog-run.md` |

## Как проходит одна задача (`work-task`)

```
Gate + claim → Scope [Decision] → Prepare (worktree) → Executor → Verifier → revmux → Lander → Filer → Done → Found problems
```

1. **Gate.** Читает задачу и эпик, ставит claim-комментарий (замок от второго агента), проверяет
   блокеры, переводит карточку в In Progress.
2. **Decision** (только при неясности): проверяет актуальность задачи, выбирает вариант, пишет
   `Decision:`-комментарий со спецификацией.
3. **Prepare.** Git worktree `.work-task/<n>` на ветке `task/<n>` от `origin/main`. Основной
   checkout не трогается — задачи идут параллельно.
4. **Executor** реализует недостающее с тестами, гоняет `ruff` и `pytest`; не коммитит.
5. **Verifier** доказывает каждый критерий приёмки именованным pytest-тестом или реальной
   командой; мок вместо проверяемой способности — `fail`.
6. **revmux** — независимое многоагентное ревью изменений вместе с тестами.
7. **Lander** применяет замечания, коммитит, rebase на `origin/main`, push в `main`, ждёт зелёный
   CI; красный чинит вперёд один раз.
8. **Filer** заводит отдельные задачи на всё, что агенты нашли попутно; они разбираются следом
   (до глубины 2).
9. **Done.** Итоговый комментарий на русском (что работает, какой тест это доказывает, коммит,
   ревью, что решили агенты, что нужно от человека), issue закрывается, карточка — в Done.

Перед итогом агент сам читает первичные доказательства и проверяет потребителя результата:
точку входа, сохранённый результат, установленный файл или работающий процесс. Пересказ другого
агента — указатель на доказательство. В итоге отдельно: реализация, установка, проверенная
способность и квалификация; закрытие задачи и CI не означают готовность продукта. Новый дорогой
опыт предлагается только с решением, которое он изменит, конечным бюджетом и действиями для
каждого исхода. Для правок текста достаточно сверки источников и затронутых проверок.

Исходы: `done`, `held` (часть сделана, остальное ждёт владельца — карточка в Need a Person с
точным описанием шага; после шага владелец возвращает карточку в Backlog), `blocked` (ждёт другую
задачу — связь «blocked by», карточка обратно в Backlog), `failed` (первая неудача — обратно в
Backlog; вторая подряд — Need a Person), `skipped`, `stop` (сломана среда — запуск
останавливается).

## Что остаётся за владельцем

По `docs/spec/AGENT_PROMPT.md` агент не делает сам: загрузку моделей, внешние и платные вызовы,
передачу записей, подключение к действующему Hermes, утверждение корпуса и порогов, расходы.
Такие задачи помечены `permission-required`; агент делает всё вокруг и останавливается в Need a
Person с названным шагом.

## Запуск

```sh
cd sound-scout-plugin
claude --permission-mode bypassPermissions   # без присмотра: любой запрос разрешения останавливает прогон
# в сессии:
/work-backlog          # или «работай бэклог», «разбери бэклог 2 параллельно»
/work-task 12          # одна задача
/new-task …            # завести задачу
```

Журнал прогона — `backlog-run.md` в корне checkout (вне git). Подробности шагов и форматов —
`.claude/skills/work-task/SKILL.md` и `references/agent-briefs.md`.
