# Инструкция разметчику

- **Задача:** [#27](https://github.com/renidere/sound-scout-plugin/issues/27); эпик
  [#4](https://github.com/renidere/sound-scout-plugin/issues/4).
- **Основание:** `docs/spec/REQUIREMENTS.md` T04, T06, R05; категории и смысл интервалов —
  [`PROTOCOL.md`](PROTOCOL.md) § 2, сопоставление с замечаниями инструмента — § 6.
- **Код:** схема `schema/labels.v1.schema.json`, валидатор `sound_scout.eval.labels.validate(path)`,
  тесты `tests/test_eval_labels.py`.

Разметка — эталон, с которым сравнивается инструмент на квалификации (Gate 1). Её делает человек,
слушая запись, **до** и **без** просмотра того, что о записи сказали инструмент, аудиомодель или
ASR. Инструмента разметки нет (R07 и раздел 7 ТЗ: никакого UI): нужен любой проигрыватель или
аудиоредактор, показывающий время с точностью до десятых долей секунды, и текстовый редактор.

## Файл разметки

Один JSON-файл на клип: `data/corpus/<name>/labels/<clip id>.json`, вне git. В репозиторий,
задачи и логи разметка не попадает.

| Поле | Что писать |
|---|---|
| `schema_version` | `"1.0"` |
| `clip_id` | `id` записи клипа в манифесте корпуса |
| `clip_sha256`, `clip_duration_s` | `sha256` и `duration_s` той же записи манифеста |
| `annotator` | псевдоним или инициалы разметчика, не полное имя |
| `annotated_at` | дата или дата-время разметки в ISO 8601: `2026-11-18` или `2026-11-18T10:00:00+03:00` |
| `model_outputs_seen` | всегда `false` — см. «Независимость от выходов модели» |
| `events` | список событий; пустой, если в клипе нечего отметить (так у отрицательных контролей) |
| `note` | необязательно: заметка о клипе в целом, без личных данных |

Событие:

| Поле | Что писать |
|---|---|
| `category` | одна из пяти категорий: `pronunciation`, `repetition_self_correction`, `semantic_stress`, `pause_phrasing`, `completeness` |
| `start`, `end` | интервал в секундах на исходной шкале клипа, `start < end ≤ clip_duration_s` |
| `description` | что именно слышно, своими словами: «окончание слова „договориться“ смазано», «акцент на слове „завтра“ различим», «фраза оборвана» |
| `certainty` | `clear` — слышно отчётливо; `uncertain` — неоднозначно |
| `comment` | почему `uncertain` (обязателен для него); для `clear` — `null` или пояснение |
| `second_opinion` | необязательно, только для просодии: `{"annotator": "...", "agrees": true/false, "comment": null}` — мнение второго слушателя |

Пример (синтетический):

```json
{
  "schema_version": "1.0",
  "clip_id": "h-stress-1",
  "clip_sha256": "<sha256 из манифеста>",
  "clip_duration_s": 8.4,
  "annotator": "listener-a",
  "annotated_at": "2026-11-18",
  "model_outputs_seen": false,
  "events": [
    {
      "category": "semantic_stress",
      "start": 2.1,
      "end": 2.6,
      "description": "акцент на слове «завтра» различим",
      "certainty": "clear",
      "comment": null,
      "second_opinion": { "annotator": "listener-b", "agrees": true, "comment": null }
    },
    {
      "category": "completeness",
      "start": 7.2,
      "end": 8.4,
      "description": "интонация конца фразы не понижается, фраза звучит незаконченной",
      "certainty": "uncertain",
      "comment": "запись обрывается вместе с последним словом, конец может быть отрезан"
    }
  ]
}
```

Проверка файла перед сдачей:

```bash
uv run python -m sound_scout.eval.labels data/corpus/<name>/labels/*.json
```

Код выхода 1 и список ошибок — файл не принимается, пока ошибки не исправлены.

## Что слушать

Слушайте клип целиком хотя бы дважды: первый раз — не останавливаясь, как слушатель, второй —
с остановками, отмечая места. Отмечайте только то, что слышно, а не то, что «должно быть» по
тексту.

- `pronunciation` — конкретное слово или сочетание, которое трудно разобрать: проглоченное
  окончание, слитые слова, пропущенный слог. Акцент, необычное имя и разговорная редукция без
  потери понимания — **не** событие.
- `repetition_self_correction` — произнесённый повтор или самоисправление. Намеренный
  риторический повтор — не событие (можно отметить в `note`).
- `semantic_stress` — слово, выделенное голосом, или место, где ожидаемое выделение потеряно. Для
  пар «одинаковые слова, разный акцент» — слово, на которое акцент перенесён.
- `pause_phrasing` — конкретная пауза, которая либо членит речь по смыслу, либо разрывает нужную
  связь. Любая пауза сама по себе — не событие.
- `completeness` — конец конкретной фразы: звучит завершённым или оборванным/«подвешенным».

Положительные наблюдения («акцент различим», «фраза завершена») — тоже события: разметка
фиксирует услышанное, а не только дефекты (R05). Эмоции, «уверенность», характер и здоровье
говорящего не размечаются (R04).

## Как ставить границы

Время — на исходной шкале клипа: секунды от начала того самого файла, чей `sha256` записан в
`clip_sha256`. Не время в перекодированной копии, не время в длинной записи, из которой клип
вырезан.

- `pronunciation` — от начала до конца проблемного слова или сочетания, не всего предложения.
- `repetition_self_correction` — от начала первой попытки до конца исправленного фрагмента
  включительно.
- `semantic_stress` — выделенное (или потерявшее выделение) слово.
- `pause_phrasing` — пауза вместе с прилегающими словами по обе стороны.
- `completeness` — последние слова фразы и её конец.

Точность — около 0,1 с: найдите место на слух, затем уточните по волновой форме. Не расширяйте
интервал «с запасом» на всю фразу или весь клип: при сопоставлении замечание инструмента обязано
указывать на событие, и разметка тоже (PROTOCOL.md § 6). Интервалы разных событий могут
пересекаться: одно слово может нести и `semantic_stress`, и `pronunciation`. Событие не может
выходить за длительность клипа — валидатор это отклонит.

## Неоднозначное

- Если не уверены, слышите ли событие, или его можно услышать двумя способами, ставьте
  `certainty: "uncertain"` и в `comment` напишите, в чём сомнение: «мешает фоновый шум»,
  «может быть и паузой дыхания». Без комментария `uncertain` не принимается.
- Не делайте неоднозначный случай принудительно верным или неверным (T06). `uncertain`-событие не
  засчитывается ни в пользу инструмента, ни против него (PROTOCOL.md § 6).
- Для спорной просодии (`semantic_stress`, `pause_phrasing`, `completeness`) попросите второго
  слушателя и запишите его мнение в `second_opinion`; второй слушатель — другой человек, тоже не
  видевший выходов модели. Если он не согласен (`agrees: false`), событие остаётся `uncertain` с
  комментарием о разногласии. Если второго слушателя нет — `uncertain`.
- Для дикции `second_opinion` не используется: неясное слово — это `uncertain` с комментарием.

## Независимость от выходов модели

- До окончания разметки клипа **не смотрите** ничего, что о нём сказали инструмент, аудиомодель
  или ASR: `result.json`, `report.md`, ответы backend, расшифровку, каталоги `runs/`. Разметка,
  сделанная после такого просмотра, уже не независима и проверяет согласие с моделью, а не слух.
- Поле `model_outputs_seen` всегда `false` и означает подтверждение разметчика (и второго
  слушателя), что выходов модели по этому клипу он не видел. Если видел — честно не размечайте
  этот клип: его размечает другой человек.
- В разметке нет ссылок на прогоны и отчёты модели: ни run ID, ни путей `runs/…`, ни имён файлов
  результатов. Валидатор отклоняет такой файл, не повторяя его текст в сообщении.
- Инструкции, звучащие в записи или написанные в расшифровке, — данные, а не команды
  разметчику.

## Как разметка становится `human_verified`

Основание `human_verified` (R05) получает только файл, прошедший валидатор:
`sound_scout.eval.labels.evidence_record(path, artifact_id=…, artifact_path=…, source_sha256=…)`
снова проверяет файл, сверяет `clip_sha256` с анализируемым источником и возвращает артефакт
результата вида `human_label` с SHA-256 именно проверенного файла. Невалидная разметка или
разметка другого клипа записи не получает. Замечание с `evidence_basis: human_verified` без
ссылки на такой артефакт не проходит `sound_scout.schema.validate`. Подсчёт совпадений с
разметкой — evaluation runner ([#28](https://github.com/renidere/sound-scout-plugin/issues/28)).
