## 2. Целевая величина

Наличие pitch accent на слове по ручной разметке RuPro (`word_pa`). Это не воспринимаемая
выделенность и не смысловой акцент. Разметчики RuPro ставили акцент по удлинению и большей
интенсивности ударного слога, затем по движению F0. Индекс `PROSODY-RULE v1` складывает те же
три признака: длительность, RMS и F0. Поэтому RuPro проверяет индекс на узкой величине, для
которой индекс задуман. PASS не говорит о смысловом акценте и о просодии вообще.

## 3. Правило

Блок ниже — правило прогона. Команды `survey`, `prepare`, `check-fresh`, `sanity` и `run`
проверяют SHA-256 текста между маркерами (без пробелов по краям, UTF-8) до любого действия и
отказывают при расхождении.

Правило 0/1 (word_pa).

  [!^]?[LH]\*?(\+[!^]?[LH]\*?)? с ровно одной "*". Иначе метка неоднозначна.

Сопоставление.
  1. Таблица -> EXB: тексты токенов и событий слоя dipl после strip, без пауз (-), (--),
     (число), (N.N). Упорядоченное выравнивание равных текстов (prosody.align, наибольшая общая
     подпоследовательность) дважды: с предпочтением раннего совпадения и на обратных
     последовательностях. Разные пары у токена — неоднозначное выравнивание.
     Событие EXB без токена допустимо; в отчёт импорта идёт его класс (хезитация, неречевое
     событие, обрыв, UNK, прочее).
  2. EXB -> граф RuPro: токен dipl графа получает время через токен base, который на него
     указывает (интервалы Praat), и word_pa спана с тем же покрытием. Если число токенов dipl
     графа равно числу событий dipl EXB, событие i — токен i графа. Иначе у записи нет времён
     RuPro. Токен i графа с другим текстом после strip не даёт событию i времени и метки.

Исключение IP (до ASR; все причины пишутся в prepare.json, первая по порядку — причина IP).
  import_check      — запись RUmo01FR_fsR, RUmo01FR_isR, RUmo02FR_fsR (проверка импорта);
  ip_value          — значение слоя ip у 1_id не равно "IP";
  ambiguous_ip      — токен IP стоит в двух IP;
  ambiguous_label   — метка токена неоднозначна по правилу 0/1;
  unmatched_token   — токен без события EXB;
  ambiguous_match   — неоднозначное выравнивание токена;
  no_rupro_times    — у записи нет времён RuPro, у токена графа нет времени, или текст токена
                      графа не равен тексту события;
  label_mismatch    — word_pa таблицы не равна word_pa графа;
  bad_interval      — у события EXB нет времени, длина <= 0, наложение на соседнее событие,
                      длина слова RuPro <= 0, срез начинается до 0 или кончается за концом MP3;
  interval_disagree — интервал IP по EXB и по словам RuPro расходятся больше чем на 1 с на
                      любом краю.

Аудио и срез.
  MP3 записи из RUEG-RuPro.zip -> ffmpeg (argv, без shell) -> моно 16 кГц float -> PCM16.
  Срез IP = [min(начало EXB, начало RuPro), max(конец EXB, конец RuPro)]; EXB — события
  токенов IP, RuPro — слова графа тех же токенов. Внутри расчёта времена слов дают только ASR.

Индекс. PROSODY-RULE v1, шаги 2–6, без изменений: ASR — prosody.local_transcriber (только
  доверенные сегменты); prosody.track и prosody.score_utterance; слова ASR сопоставляются со
  словами IP после prosody.normalize по порядку.

Метрика (считается ровно один раз).
  AUC — доля пар «слово 1 / слово 0 одной IP», в которых индекс слова 1 выше (ничья — 0,5), по
        всем парам.
  CI  — 95 % интервал AUC: кластерный бутстреп по говорящим (prosody.bootstrap_ci по суммам
        говорящего; обе записи говорящего — его кластер), 1000 повторов, seed 0, перцентили 2,5
        и 97,5.
  coverage — доля слов 1 оставленных IP, сопоставленных со словом ASR.
  Пары — оценённые пары; IP с парами и говорящие с парами — хотя бы с одной парой.

Свежесть (check-fresh). Ни один SHA-256 MP3 (байты члена RUEG-RuPro.zip), WAV и PCM среза не
  совпадает с SHA-256: WAV архива RINCO v0.1 (серии 1–3); WAV и PCM corpus/pilot-1/clips и
  openstt-pool и sha256 из corpus/pilot-1/provenance.json; PCM клипов Gate 0; клипов

Санитарная стадия (до основного прогона; потолок попытки 15 мин). Как в 0034:
  R0 — первые 20 реплик серии 3 воспроизводятся с отклонением индекса не больше 1e-6, квитанция
  ASR совпадает; S2' — тишина, розовый шум и тон 440 Гц (5 с) дают 0 оценённых слов

## 6. Ограничения вывода

- Цифры согласия разметчиков RuPro для наличия акцента нет. Статья даёт каппу только для границ
  IP (0,651 на 8 записях билингвов).
- `word_pa` — проекция слоговой пометы на слово при сборке корпуса. Метка ручная, переносит её
  машина.
- Речь спонтанная, запись со смартфона, IP короткие: медиана — 2 слова (у серии 3 — 5).
- Главный риск — coverage < 0,70, это INCONCLUSIVE.
- 37 говорящих — кластеры CI. Интервал по записям идёт в отчёт для сравнения.
- PASS говорит о наличии pitch accent по акустике внутри одной IP, не о смысловом акценте.

## 7. Шаги

Команды — из корня дерева, `python -m sound_scout.eval.prosody_rupro <команда>`, конфигурация —
`docs/eval/PROSODY-CONFIG.md`:

1. `verify` — источники против пинов. `survey` — импорт и счёт без клипов (раздел 5).
2. Дерево `prosody-rupro-1` (раздел 4.2), `verify-frozen`.
3. Из дерева: `prepare` (срезы, `check-fresh`, `prepare.json` и его SHA-256), один раз.
4. Отчёт импорта в #199 — только числа.
5. Из дерева: `sanity`, затем один `run` под `systemd-run --user --scope -p MemoryMax=8000000000
   -p MemorySwapMax=0`, `OMP_NUM_THREADS=4`. Перед ними агент проверяет, что тяжёлой работы на
   станции нет.
6. Отчёт `docs/eval/<дата>-prosody-rupro-1.md` и строка результата здесь.

Каталог — `data/prosody-rupro-1/`, вне git. Тексты, метки по словам и аудио не попадают в git,
задачи и логи.
