## 4. Почему так

- **Один шаблон с аудио и без него.** Разница условий — только звук. Выигрыш audio тогда нельзя
  объяснить тем, что аудиозапрос несёт меньше текста.
- **Расшифровка на контролях.** На тишине модель видит те же слова. Ответ `1` или `2` показывает,
  что модель берёт ответ из текста, а не из звука.
- **Два порядка.** Модель может выбирать позицию, а не слово. Доля ответа `1` и расхождение порядков
  это показывают.
- **Одна реплика на WAV.** Кластеры bootstrap не делят запись.
- **Контроли `S0`, `N1`, `T1` дня 2026-11-19.** На них этот runtime в 0024 ответил «да» на P по
  `S0` и `N1`. 12 клипов E-C не берутся: поручение называет три контроля.

## 5. Запуск

Конфигурация — как в `docs/eval/PROSODY-CONFIG.md`: `data_root` — `data/` основного checkout,
`[network] allow = false`, файл в `SOUND_SCOUT_CONFIG`. Из корня дерева на коммите `main`:

```bash
uv run python -m sound_scout.eval.forced_choice prepare
systemd-run --user --scope -q -p MemoryMax=18000000000 -p MemorySwapMax=0 -p AllowedCPUs=0-7 -- \
  uv run python -m sound_scout.eval.forced_choice run
uv run python -m sound_scout.eval.forced_choice analyze
```

- `prepare` не запускает сервер и не шлёт запросов. Файл с другим содержимым он не перезаписывает.
- `run` до старта сервера проверяет блок правила, `set.json`, `plan.json`, 23 WAV, план против
  `set.json`, cgroup, CPU, память хоста, занятость хоста и пины. Любое расхождение — отказ без
  попытки.
- Попытка — `data/gate0/forced-choice-205/attempts/<k>/`: `run.json` (пины, argv, версия, лимиты,
  коммит и SHA-256 кода, причина остановки), `trace.jsonl`, `requests/` (без base64 аудио),
  `responses/` (сырые ответы), `server.log`, `analysis.json` (без слов), локальный `report.md` со
  словами.
- Не запускать вместе с прогоном #199 или полным `pytest`.
- Попытка с `run.json` уже есть — `run` отказывает. Новая попытка требует решения владельца:
  `run --owner-decision <ссылка на решение>`. Ссылка и номера прежних попыток идут в `run.json`.

**Оценка времени (гипотеза, не измерение).** 0024 на `-t 12`: audio-вопрос — медиана 41,1 с,
text-only — 5,1–5,4 с. На `-t 8` при линейном префилле ×1,5: ≈ 65 с на audio-запрос и ≈ 8 с на
text. Прогон ≈ 46 × 65 + 40 × 8 с ≈ 55 мин из 75. При таймауте первого audio-запроса прогон
закончится через ≤ 2 мин как `incomplete`.

## 6. Что опыт не устанавливает

- Причину прежнего провала P в 0028: runtime и dtype другие. Ответы P 0028 на тех же 20 репликах
  `analyze` показывает описательно, вне вывода.
- Готовность backend: опыт не Gate 0 и не Gate 1.
- Слух модели на других задачах: проверка произношения Q-S, другая модель, другой runtime или
  облачный контроль требуют нового решения владельца.
