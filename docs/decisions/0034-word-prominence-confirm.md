## 1. Почему этот набор

Серия 3 `prosody-measure-1` дала PASS post hoc: AUC 0,761, CI 0,737–0,783, coverage 0,807, 8 251
пара, 208 файлов. Выборку серии 3 определили после результатов серии 2. Это не подтверждённое
измерение.

Свежего материала RINCO нет. Серии 1–3 взяли 209 из 228 пар EAF/WAV. Остальные 19 пар — `pilot-1`
(в том числе held-out Gate 1) и 6 пар 4-News по E1/E2, которые уже читала серия 2. Других
корпусов с пословной пометой выделенности на станции нет. Открытой загрузки CoRuSS нет.

Выбран вариант 3 Decision: 160 клипов Open STT `asr_calls_2_val` со станции. Их не брали серии 1–3,
`pilot-1` и пул #81. Выделенность размечает человек. Загрузки нет. Меняются жанр (телефонные
звонки) и разметчик (не эксперт RINCO). Поэтому разметчик сначала проходит калибровку на 40
репликах RINCO с известной пометой. Каппа ниже 0,40 даёт INVALID.

## 5. Ограничения вывода

- Кластер бутстрепа — клип: идентификаторов говорящих в Open STT нет. Если у одного говорящего
  несколько клипов, CI выйдет уже истинного.
- Разметчик — не эксперт RINCO. Каппа ≥ 0,40 означает умеренное согласие, не совпадение.
- Калибровочные реплики (студия RINCO) звучат иначе, чем звонки. Разметчик может отличить их на
  слух; слепота пакета — только по id и порядку.
- Эталонный текст Open STT может не совпадать с речью. Разметчик пропускает такой клип
  (`skip_reason`).
- PASS говорит об акустической выделенности внутри одного клипа, не о смысловом акценте.

## 6. Шаги

Команды — из корня дерева, `python -m sound_scout.eval.prosody_confirm <команда>`:

1. `prepare` — Q1, отбор 160 клипов, калибровка, `check-fresh`, пакет разметки. Один раз.
2. `check-fresh` — повторная проверка свежести по `prepare.json` и файлам клипов.
3. Разметка человеком по `docs/eval/PROSODY-LABELING.md` — шаг владельца.
4. `import <sheet.csv>` — проверка листа, каппа, `labels.json`, SHA-256 листа. Первый принятый
   лист окончателен.
5. `sanity` — R0 и S2' под `systemd-run --user --scope -p MemoryMax=8000000000
   -p MemorySwapMax=0`, `OMP_NUM_THREADS=4`.
6. `run` — один основной прогон в том же scope, `result.json` с вердиктом.
7. Отчёт `docs/eval/<дата>-prosody-confirm-1.md` и строка результата в этом файле.

Перед `sanity` и `run` агент проверяет, что на станции нет другой тяжёлой работы (`llama-*`,
полный `pytest`, другой прогон модели).

Каталог — `data/prosody-confirm-1/`, вне git. Данные серий 1–3, `pilot-1` и Gate 0 только
читаются. Тексты и аудио не попадают в git, задачи и логи.
