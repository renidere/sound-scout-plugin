## 2. Протокол

### 2.1. Клипы

Все клипы, которые уходят в модель, — 16 kHz mono PCM s16 WAV. Подготовка речевых клипов:
исходник 48 kHz → `ingest.decode` → `channels.choose_mono` → `prepare.mono16k` (ffmpeg, как в
`analyze`) → `asr.transcribe` (faster-whisper из конфигурации оператора, offline) только для
границ слов. Слова, транскрипт и номера слов пишутся только в `data/gate0/<дата>/words.json`
(вне git); здесь — номер целевого слова и его интервал в секундах, без самого слова.

| id | источник | что сделано |
|---|---|---|
| `B1`, `B2`, `B3` | `H01`, `H02`, `H03` | Praat `To Manipulation 0.01 75 600` → `Get resynthesis (overlap-add)` без изменения тиров (нейтральный ресинтез: оба члена пары проходят одну обработку) |
| `V1` | тот же Manipulation, что `B1` | PitchTier `Multiply frequencies` на интервале целевого слова, ×2^(4/12) (**+4 полутона**) |
| `V2` | тот же Manipulation, что `B2` | DurationTier: 1,0 до слова, **×1,6** на интервале слова (точки t0−1 мс, t0, t1, t1+1 мс), 1,0 после |
| `V3` | тот же Manipulation, что `B3` | одновременно **+3 полутона** и **×1,3** на целевом слове |
| `S0` | синтез | цифровая тишина, 10,0 с, все отсчёты 0 |
| `N1` | синтез | розовый шум 10,0 с, RMS −30 dBFS, `numpy.random.default_rng(0)`, спектр 1/f через FFT |
| `T1` | синтез | синус 440 Гц, 10,0 с, амплитуда 0,1 (пик −20 dBFS), фронты 10 мс |
| `E0` | — | пустой вход (0 отсчётов PCM): не клип, отклоняется `review.check_payload` (`AudioPayloadMissing`) до какого-либо HTTP-вызова; trace фиксирует 0 обращений к серверу (T03) |

Интенсивность не меняется. Если после ресинтеза пик члена пары > 0,99, оба члена пары
масштабируются одним коэффициентом до пика 0,99, коэффициент записывается в `manifest.json`.
`V1`–`V3` — **синтетически изменённые** клипы: они не заменяют естественные пары и сами по себе
не дают READY.

**Выбор целевого слова — механический, до прогона.** Из слов ASR исходного клипа (сегменты,
которым доверяет `asr.trusted_segments`, решение 0005) берутся кандидаты: не первое и не последнее
слово клипа, вероятность слова ≥ 0,80, длительность 0,25–1,0 с. Среди них — слово с наименьшей
медианой F0 (Praat `To Pitch (ac)` 0,01 / 75 / 600 Гц, только озвученные кадры на интервале
слова в исходнике; слово без озвученных кадров не кандидат), при равенстве — более раннее. Нет
кандидата — пара не строится и в правиле считается неразличённой. В вопрос подставляется слово
без пробелов и пунктуации по краям.

### 2.2. Варианты вопросов (фиксированы, отчитываются все)

- **A — инструкция audio review.** Текст — упакованный `src/sound_scout/AUDIO_REVIEW_PROMPT.md`
  (байт в байт `docs/spec/AUDIO_REVIEW_PROMPT.md`), версия — SHA-256
  `53b9fd53bfeb1eb78b2b3a837824807563a84561b0bccc2e9cd1b1157a0917ca`; при ином хэше `run`
  останавливается. После текста инструкции дословно:
  `\n\nДоверенные поля: <JSON clip_id, duration_s, task=null, intent=null>\n\nОтвет — один JSON-объект с полями observations, unlocalized_observations, uncertainties, limitations; category — одно из: pronunciation, repetition_self_correction, semantic_stress, pause_phrasing, completeness.`
  Ответ проверяет `review.validate_response`. Задаётся всем 9 клипам. Transcript-only — для
  `B1..B3`: аудио нет, перед строкой «Доверенные поля» вставлено
  `\n\nРасшифровка (вместо аудио): «<ASR-текст исходного клипа>»`.
- **K — что слышно.** `K1`: «Что слышно на этой записи? Ответь одним словом из списка: речь,
  музыка, тон, шум, тишина.» `K2`: тот же вопрос со списком в обратном порядке «тишина, шум, тон,
  музыка, речь» (контроль позиционной предвзятости). Задаются всем 9 клипам.
- **P — выделение слова.** Со звуком: «Выделено ли на этой записи слово «{word}» голосом сильнее
  соседних слов? Ответь одним из вариантов: да; нет; нет речи — если на записи нет речи.»
  Задаётся `B1..B3`, `V1..V3` со словом своей пары и `S0`, `N1`, `T1` со словом пары 1. Это
  text-assisted зонд: слово названо текстом (R03). Transcript-only baseline: «Вот расшифровка
  записи: «{transcript}». Выделено ли в ней слово «{word}» голосом сильнее соседних слов? Ответь
  одним из вариантов: да; нет; нет речи — если на записи нет речи.» — по одному на пару
  (транскрипт членов пары один и тот же по построению, текст не может их различить).

Тексты вопросов — константы `QUESTIONS` модуля `sound_scout.eval.gate0`; SHA-256 их
канонического JSON записывается в `manifest.json` при `prepare` и сверяется при `run`.

**Разбор закрытых ответов:** нижний регистр, `ё→е`, убрать пробелы, кавычки, markdown и
пунктуацию по краям; варианты ищутся как целые слова, длинные раньше коротких («нет речи» раньше
«нет», найденный вариант вырезается из текста); ровно один найденный вариант — ответ, иначе
`invalid`.

### 2.3. Настройки inference

`POST /v1/chat/completions`, одно сообщение `user`, `content = [input_audio (WAV base64,
format "wav"), text]` (для transcript-only — только `text`). `temperature 0`, `seed 0`,
`cache_prompt false`, `chat_template_kwargs {"enable_thinking": false}`; `max_tokens` 8 для
закрытых вопросов, 1024 для инструкции; для инструкции — `response_format {"type":
"json_object"}`. Повторов нет: каждый запрос — один раз (R11). Наличие `reasoning_content`
записывается.

Лимиты владельца: ≤ 10 клипов, каждый ≤ 30 с; клиентский таймаут запроса 600 с; RSS процесса
сервера опрашивается из `/proc/<pid>/status` каждые 0,5 с, при `VmRSS > 18·10⁹` байт сервер
останавливается. Превышение любого лимита завершает прогон: оставшиеся запросы не отправляются и
считаются непрошедшими, ограничение записывается.

Итого запросов синтетического прогона: K 18 + P 9 + P-текст 3 + A 9 + A-текст 3 = **42**,
локально, стоимость 0.

### 2.4. Trace

На каждый запрос — строка `data/gate0/<дата>/attempts/<k>/trace.jsonl`: номер, вариант, клип,
модальность (`audio` / `text`); SHA-256 отправленного WAV-файла и SHA-256 PCM, длительность,
частота; `usage.prompt_tokens`, `completion_tokens`, `finish_reason`, `timings` сервера; wall
time клиента; RSS сервера до, после и пик за запрос; HTTP-статус и ошибка.

**Доказательство аудиомаршрута:** для каждого audio-запроса число текстовых токенов того же
сообщения без аудио считается через `/apply-template` + `/tokenize` сервера (без inference);
аудиотокены = `prompt_tokens − текстовые`, должны быть ≥ 20 × длительность клипа. Если этих
эндпоинтов нет — по K1 (одинаковый текст для всех клипов) берётся наклон МНК `prompt_tokens` от
длительности, он должен быть ≥ 20 токенов/с.

`manifest.json` (при `prepare`): коммит и SHA-256 кода, хэш правила, хэш промпта A, хэш
вопросов, клипы с хэшами. `run.json` (при `run`): argv, `llama-server --version`, SHA-256 весов,
CPU, потоки, load average, время загрузки модели, `VmHWM`, причина остановки. Сырые ответы —
`responses/<n>.json` дословно; тело запроса — `requests/<n>.json` без base64, с хэшами аудио.

## 4. Результаты

### Попытки 1 и 2 (2026-11-18, `attempts/1/`, `attempts/2/`): отказ до старта сервера

`run` остановился на проверке P2 до запуска `llama-server`: SHA-256 файла
`gemma-4-E4B-it-Q8_0.gguf` на станции был `c1a02c7f3b3f64dd115595896075a67ca0b953243c960f05c3f8c427ba403bff`
вместо `49008e7c…` из `docs/dependencies.md` §3.1 (размер совпадал). Сервер не запускался,
запросов к модели — 0. Разбор владельца
([комментарий 6988464481](https://github.com/renidere/sound-scout-plugin/issues/23#issuecomment-6988464481)):
в файле отличался ровно один байт — один перевёрнутый бит, тихий аппаратный сбой после проверки;
файл заменён проверенной копией с SHA-256 `49008e7c…`. Отказ на непроверенных весах сработал как
задумано; код этой проверки не менялся.

### Попытка 3 (2026-11-18, `attempts/3/`): прогон spike

- **P1:** `E0` отклонён `review.check_payload` (`clip 'E0' has no audio payload`) до HTTP-вызова;
  обращений к серверу по `E0` — 0.
- **P2:** SHA-256 обоих файлов весов совпали с §3.1; промпт A — `53b9fd53…0917ca`; хэши правила

- **Отрицательные контроли, K1 и K2 (дословно):** на цифровую тишину `S0`, розовый шум `N1` и тон

- **Отрицательные контроли, P (дословно):** `нет` на всех трёх; варианта «нет речи» модель не

## 5. Вердикт

**Вердикт: NOT READY** — механически по правилу раздела 3, попытка 3
(`python -m sound_scout.eval.gate0 verdict --date 2026-11-18` → `{"verdict": "NOT READY", "reason":
"C: не прошли 6 из 12 пунктов контролей: ['K1(S0)', 'K2(S0)', 'K1(N1)', 'K2(N1)', 'K1(T1)', 'K2(T1)']"}`).

- Предусловия P1–P3 выполнены: прогон действителен, это вердикт о модели, а не о протоколе.
- **C не проходит** (6 из 12 пунктов): на тишине, шуме и тоне модель называет звук речью. По
  правилу это «выдуманная речь на контроле», и одного этого достаточно для NOT READY.
- **S тоже не проходит** (0 из 3 синтетических пар различено): даже грубый контраст +4 полутона /
  ×1,6 на одном слове не меняет ответ модели. По правилу при не прошедшем C это уже не влияет на
  вердикт, но означает, что естественные пары модель тем более не различит.

Правило после просмотра ответов не менялось: блок раздела 3 и его SHA-256 совпадают с
записанными в `manifest.json` при `prepare`, `run` это проверил (P2).

**Следствие (Decision 6986704763, «Следствия исходов»):** Gemma 4 E4B-it на этом протоколе не
слышит различий, которых требует Gate 0, и выдумывает речь на неречевых контролях; backend не
упаковывается, `backend` остаётся `none`, `doctor` для `audio_review` — `permission_required`.
Естественные пары для этого backend не нужны: вердикт синтетического прогона окончательный.
Замену backend выбирает владелец (запасной кандидат по `docs/spec/REQUIREMENTS.md` §9 —
Borealis-5b-it).

## 6. Ограничения

- Один прогон, одна модель и одна квантизация (Q8_0 + mmproj BF16), декодирование
  детерминированное (`temperature 0`, `seed 0`). Другие квантизации, другой runtime или другая
  формулировка вопросов здесь не проверялись; подбор вопроса под результат протокол запрещает.
- Пары синтетические (Praat PSOLA): ресинтез даёт артефакты, и естественное логическое ударение
  отличается от сдвига F0/длительности. Здесь это не смягчает вывод: провал на синтетике по
  правилу — NOT READY.
- Один говорящий, три development-записи владельца, не held-out материал; Gate 0 — не
  квалификация Gate 1 и не `validated_ru`.
- Вопрос P — text-assisted зонд (слово названо текстом, R03); его ответы на контролях (`нет`)
  проходят C2, но при K1/K2 = «речь» не означают, что модель отличает отсутствие речи.
- Transcript-only A: при `enable_thinking: false` сервер всё равно вернул `reasoning_content`, и
  ответ упёрся в `max_tokens` 1024; это наблюдение о шаблоне чата Gemma 4 в llama.cpp b12359 на
  длинном текстовом запросе, в вердикт не входит.
- Задержка против бюджета R11 (клип до 30 с — до 60 с обработки): закрытые вопросы — 6,8–12,9 с
  на клип 10–16 с; инструкция A со звуком — 45,6–84,5 с на клип, то есть один вариант A на
  `B3` (13,3 с) уже вне бюджета, а A без звука — 311–338 с. Загрузка модели — 16,0 с отдельно.
  Измерено на i5-14400, 12 потоков, при параллельной чужой нагрузке (load average ≈ 6).
- Память: пиковый RSS 10,09 GB при `-c 4096`, укладывается в лимит владельца 18 GB.
