## Вопрос

Слепой пакет разметки (`annotation-prep-1`) раздаёт клипы под нейтральными ID (`A001`…,
`D001`…), а связь с исходными записями корпуса лежит только в
`operator-private/alias-map.json`. Как принять заполненную разметчиком копию так, чтобы не
испортить шаблоны, `pilot-1` и прежние сдачи, не выдать шаблон за «событий нет» и не перенести
dev-запись в held-out?

## Правила

1. **Команда.** `sound-scout eval import-labels <сдача> --package <пакет>`. Сдача — одна
   распакованная рабочая копия слепой папки: читаются только `labels/<ID>.json` и необязательный
   `review.csv`. Аудио, `clip-index.json`, слепые папки и ZIP пакета не читаются; модель, ASR и
   сеть не вызываются.
2. **Единственный источник ожиданий — `alias-map.json`.** Нейтральный ID, `clip_sha256`,
   длительность, исходный ID, `source_corpus` и split берутся из карты. Карта без файла, с другим
   `kind`, с неверным полем или повтором ID отказывает всю команду; сообщение называет поле, но
   не значение. Абсолютные пути карты (`source`, `source_label`, `original_record.path`) не
   выводятся и не попадают в квитанцию.
3. **Подписан / не подписан.** Файл не подписан, когда `annotator` и `annotated_at` оба пусты.
   Неподписанный шаблон с `events: []` получает статус `unsigned`: он копируется в `submission/`,
   но не валидируется, не попадает в `mapped/` и не считается «событий нет». Неподписанный файл с
   событиями — отказ `unsigned_with_events`. Подписанный файл проходит
   `sound_scout.eval.labels.validate`.
4. **Коды отказа на файл:** `unexpected_entry`, `unknown_id`, `not_json`, `id_mismatch`,
   `changed_sha256`, `changed_duration` (точное равенство чисел JSON), `unsigned_with_events`,
   `invalid_labels` (строки валидатора под файлом, без текста описаний), `duplicate_id`,
   `manifest_mismatch`, `review_conflict`; для `review.csv` — `bad_review_csv`, `unknown_id`,
   `duplicate_id`. Сдача внутри каталога пакета, отсутствие или пустота `labels/` — отказ всей
   команды.
5. **Атомарность.** Любой отказ: ничего не пишется, на stderr по строке
   `refused: <файл>: <код>`, последняя строка — `import refused: <N> files, nothing written`,
   код выхода 1. Частичного импорта нет: его нельзя было бы повторить тем же каталогом без
   дубликатов.
6. **Повтор.** Подписанный файл, уже `imported` в прежней сдаче того же пакета с тем же SHA-256,
   получает `already_imported` и повторно не импортируется: разметчик может сдавать накопительно.
   Тот же ID с другими байтами — `duplicate_id`. Сдача без нового подписанного файла — отказ
   `nothing to import`.
7. **Раскладка.** Новый каталог `<корпус>/<пакет>-returns/<NNN>/` (следующий номер после
   максимального) собирается во временном соседнем каталоге и переносится `os.rename`; при любой
   ошибке временный каталог удаляется. Внутри: `submission/` — побайтовая копия `labels/` и
   `review.csv` с проверкой SHA-256; `mapped/<source_corpus>/<исходный id>.json` — только новые
   подписанные файлы, где заменён только `clip_id` (через разбор JSON, не текстовой заменой), копия
   повторно проходит валидатор; `import.json` — квитанция со статусом, split из карты, SHA-256 и
   `manifest_check` каждой записи, без абсолютных путей. Каждый файл в `mapped/` уже в формате
   runner, но одна сдача покрывает лишь часть split: полный `eval run --labels` — объединение
   `mapped/<source_corpus>/` всех сдач, где размечен каждый клип split.
8. **Split и манифест только читаются.** Если `<корпус>/<source_corpus>/manifest.json` есть,
   запись с исходным ID обязана быть в нём с тем же split и `sha256`, иначе `manifest_mismatch`;
   если нет — `manifest_check: "absent"`. Импортёр нигде не задаёт split и не пишет манифест:
   перенос dev → held-out невозможен по построению.
9. **Вне рамок.** Листы сверки ASR (`03-asr-after-first-pass`) импортируются отдельно; решение о
   составе новой версии корпуса принимает владелец после импорта.

## Последствия

- Импорт настоящей сдачи возможен только после человеческой разметки (#29); запускает его
  оператор на своём пакете.
- `mapped/` — это ещё не разметка корпуса `pilot-1/labels/`: перенос туда и новая версия корпуса —
  отдельное решение.
